# Gems Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A `gems` mode per country: small municipalities that meet the user's thresholds for internet, city, airport and hospital.

**Architecture:**
- `web/src/gems.ts` holds the pure logic: filters, `judge`, hash parsing and writing, and tooltip text.
- `main.ts` adds the mode. Entering it loads the airports, internet and hospitals data. It then runs `judge` over the features and sets the feature-state `gem` (0 other, 1 near, 2 gem, 3 too big). The fill reads that state.

**Tech Stack:** TypeScript, MapLibre, vitest (new dev dependency).

**Spec:** `docs/superpowers/specs/2026-11-22-gems-design.md`

## Global Constraints

- No pipeline or data changes. The four existing JSONs per country are the only inputs.
- **Existing modes and hashes are unchanged.** `#gems` alone means Spain.
- **Defaults:**
  - pop 20000;
  - net fixed, 100 Mbps, estimates on;
  - city tier 2, 60 min;
  - air tier 2, 90 min, year-round;
  - hosp tier 2, 45 min.

## Review Focus

1. **Missing values** (no internet value, an unreachable `-1`, a dataset that failed to load) must fail the criterion, never pass it. Tested in Task 1.
2. **A place that is itself a city of the chosen tier,** and a hospital "in town" (0), both pass. Tested in Task 1.
3. **A hash round-trip** with criteria switched off, and garbage hash values, must fall back to the defaults. Tested in Task 1.
4. **A country switch while in gems mode:** the states must be recomputed for the new country's features, with no stale classes. Checked in the browser in Task 2.
5. **Performance on France** (about 35k communes): changing a control must stay responsive (under about 0.5 s). Checked in the browser in Task 2.

### Task 1: gems.ts logic (TDD)
- `npm i -D vitest`, and add the `"test": "vitest run"` script.
- **Code** in `web/src/gems.ts`:
  - `export interface GemFilters { pop: number | null; net: { kind: 'fixed'|'mobile'|'either'; min: number } | null; est: boolean; city: { tier: Tier; max: number } | null; air: { tier: Tier; max: number } | null; summer: boolean; hosp: { tier: Tier; max: number } | null }`;
  - `DEFAULTS`;
  - `type Crit = 'net'|'city'|'air'|'hosp'`;
  - `judge(p, f) -> { cls: 0|1|2|3; checks: { crit: Crit; value: number | null; ok: boolean }[] }`;
  - `parseHash(query: string) -> GemFilters`;
  - `formatHash(f) -> string`.
- **Tests** in `web/src/gems.test.ts`:
  - all pass → 2;
  - one fail → 1;
  - two fails → 0;
  - pop over the limit → 3, even when everything passes;
  - pop unknown → small;
  - `-1` city → fail;
  - a missing internet key → fail;
  - an estimate counts only when `est` is on;
  - `either` takes the best of fixed and mobile;
  - `dt <= tier` passes the city criterion;
  - `hm` 0 passes;
  - the summer key (`s2` vs `y2`);
  - an off criterion is not in `checks` and never fails;
  - the hash round-trip, and garbage falls back to the defaults.
- Commit.

### Task 2: web mode
- **index.html:**
  - a "Gems" mode button;
  - a `#gems-controls` block with selects and checkboxes (`data-for="gems"`);
  - a `#gems-list`;
  - per-country "How this map is made" text (shared, no `data-country`).
- **main.ts:**
  - `Mode` gains `'gems'`;
  - entering it awaits `ensureAirports`, `ensureInternet` and `ensureHospitals`;
  - `applyGems(map)` loops over `geo.features`, sets the feature-state `{gem}`, and gathers counts and the list;
  - the fill is `['match', ['feature-state','gem'], 2, gold, 1, pale, 3, urban, other]`;
  - controls → filters → `writeHash` (`#cc/gems?…`) → `applyGems`, debounced 100 ms;
  - the tooltip comes from `judge().checks`;
  - list clicks fit the feature's bbox;
  - `setCountry` reapplies when the mode is gems;
  - the tier, seasonal and mobile rows are hidden in gems mode.
- **style.css:** the controls and the list.
- **Checks:** `npm run build`, `npm test`. In the browser:
  - Spain and France gems;
  - the controls change the counts;
  - a reload keeps the settings;
  - switching country in gems mode;
  - the other 4 modes unchanged;
  - France timing.
- Commit, then the final review, the fix pass, and a local merge into `main`.
