# Internet Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measured internet speed (download, upload, latency; fixed and mobile) per Spanish municipality from Ookla open data, as JSON + CSV and as a third "Internet" view on the map.

**Architecture:** `pipeline/geo.py` decodes the site's TopoJSON boundaries and locates points in municipalities. `pipeline/compute_internet.py` pulls the Spain bounding box of the last 4 quarterly Ookla Parquet files from S3 with DuckDB, caches them, assigns tiles to municipalities by centre point, aggregates test-weighted means and writes `internet.{json,csv}`. The web page gets a third mode that reuses the choropleth with per-metric colour bins.

**Tech Stack:** Python 3.12 + DuckDB (new dependency, `pipeline/requirements.txt`), pytest; TypeScript, Vite, MapLibre GL 5.

**Spec:** `docs/superpowers/specs/2026-11-21-internet-design.md`

## Global Constraints

- **Source:** `s3://ookla-open-data/parquet/performance/type={fixed|mobile}/year=YYYY/quarter=Q/YYYY-MM-01_performance_{fixed|mobile}_tiles.parquet` (region us-west-2, anonymous).
  - Columns used: `quadkey, tile_x (lng), tile_y (lat), avg_d_kbps, avg_u_kbps, avg_lat_ms, tests, devices`.
- **Period:** the latest 4 quarters that have a `.parquet` file for **both** types (today: 2025-Q4 … 2026-Q3).
- **Bounding box pre-filter:** `tile_x BETWEEN -18.5 AND 4.5 AND tile_y BETWEEN 27.4 AND 44.0`. Point-in-polygon then drops everything not in a Spanish municipality.
- **Aggregation:** per municipality and type, test-weighted means over all tiles and quarters.
  - Download/upload in Mbps, rounded to 1 decimal; latency in ms, integer.
  - `tests` and `devices` are summed over tiles and quarters.
- **Minimum evidence:** a value needs `tests >= 20 and devices >= 5`, otherwise `null`. Counts are always published.
- **JSON row:** `[f_down, f_up, f_lat, f_tests, f_devices, m_down, m_up, m_lat, m_tests, m_devices, population]`.
- **CSV header:** `code,name,province,population,fixed_down_mbps,fixed_up_mbps,fixed_latency_ms,fixed_tests,fixed_devices,mobile_down_mbps,mobile_up_mbps,mobile_latency_ms,mobile_tests,mobile_devices`. Written with `common.write_csv` (empty cell for `None`, `.csvt` sidecar).
- **Licence text, verbatim on the page and in the README:** "Speedtest® by Ookla® Global Fixed and Mobile Network Performance Maps, CC BY-NC-SA 4.0. The internet data derived here is shared under the same licence."
- **Web:**
  - Modes are `Cities | Airports | Internet`, hash `#internet`. The metric buttons are `Download | Upload | Latency` (default Upload), with a "Mobile instead of fixed broadband" checkbox (default off).
  - Colour bins, best (light) → worst (dark), plus grey for "not enough speed tests":
    - Download Mbps: ≥300 · 100–300 · 50–100 · 25–50 · 10–25 · <10
    - Upload Mbps: ≥100 · 50–100 · 20–50 · 10–20 · 3–10 · <3
    - Latency ms: <20 · 20–35 · 35–50 · 50–80 · 80–120 · ≥120
  - Headline thresholds: download <25 Mbps, upload <10 Mbps, latency >80 ms.
- No GitHub Actions changes. The pipeline runs locally.

## Review Focus

1. **Tiles in Portugal, France, Andorra, Morocco or at sea** inside the bounding box must be dropped, never attached to the nearest Spanish municipality. Test in Task 1.
2. **Enclaves and holes:** Llívia (an enclave inside France) and Condado de Treviño (inside Álava, but part of Burgos) must locate correctly, which needs multipolygons and holes. Test in Task 1.
3. **Many tests from few devices** (one household testing daily): 40 tests from 2 devices gives `null` values but published counts. Test in Task 2.
4. **Quarter listing quirks:** S3 lists folder keys (`.../quarter=2/`) and a quarter may exist for fixed but not yet for mobile. Only quarters with both files count. Test in Task 2.
5. **Municipality with no tiles at all:** row with `null` values and `0` counts, not missing from the JSON/CSV. The CSV still has 8,132 rows. Test in Task 2.

### Task 2: Aggregation and outputs

**Files:**
- Create: `pipeline/compute_internet.py` (pure functions in this task; fetching and CLI in Task 3)
- Test: `pipeline/tests/test_internet.py`

**Interfaces:**
- Consumes: `geo.MuniIndex.locate`, `common.write_csv`, `common.PLACES_FILE`.
- Produces:
  - `latest_quarters(keys: list[str], n=4) -> list[tuple[int, int]]` takes S3 keys of both types and returns `[(year, q), ...]` ascending. A quarter counts only if a `.parquet` key exists for fixed **and** mobile.
  - `Tile = tuple[float, float, int, int, int, int, int]`, holding `(lng, lat, d_kbps, u_kbps, lat_ms, tests, devices)`.
  - `aggregate(tiles: dict[str, list[Tile]], locate) -> dict[str, dict[str, list]]`
    - The input is keyed by type (`"fixed"`/`"mobile"`).
    - The output is code → type → `[down_mbps, up_mbps, lat_ms, tests, devices]`, with values `None` below the minimum evidence.
    - Only codes that received tiles appear.
  - `MIN_TESTS = 20`, `MIN_DEVICES = 5`.
  - `build_output(places, agg, quarters) -> dict`: the JSON shape from the spec.
    - Every municipality in `places` gets a row; with no tiles it reads `[None, None, None, 0, 0] * 2 + [pop]`.
    - `params` carries `source`, `licence`, `quarters` (as `"2026-Q1"` strings), `min_tests`, `min_devices` and `notes`.
  - `internet_csv_rows(output, munis) -> (header, rows)`, with the header from Global Constraints.

- [ ] **Step 1: Write the failing tests** (no network; `locate` is a lambda or the real `MuniIndex`).
  - `test_latest_quarters_needs_both_types`: keys include folder-only entries and a `2026 Q3` fixed file without a mobile one. The function returns the 4 latest complete quarters, ascending.
  - `test_test_weighted_mean`: two tiles in one code. Tile 1 has 10 tests at 100,000/10,000 kbps and 20 ms; tile 2 has 30 tests at 20,000/2,000 kbps and 60 ms. Expect down `40.0`, up `4.0`, lat `50`, tests `40`, devices = sum.
  - `test_minimum_evidence`: 40 tests from 2 devices → values `None`, counts `40, 2`; 19 tests from 10 devices → `None`; 20 tests from 5 devices → values set.
  - `test_unlocated_tiles_dropped`: when `locate` returns `None` the tile is ignored.
  - `test_output_has_every_municipality`: with the real `places.json` and empty `agg`, `len(out["m"]) == 8132`; a row is `[None, None, None, 0, 0, None, None, None, 0, 0, pop]`.
  - `test_internet_csv`: header as specified; `None` becomes an empty cell after `write_csv`; codes are zero-padded; the `.csvt` first entry is `"String"` and the `*_tests` columns are `"Integer"`.

  - `loadInternet(): Promise<InternetData | null>`.
  - `internetProps(row) -> Record<string, number | null>`, with keys `fd, fu, fl, ft, fv, md, mu, ml, mt, mv` (v = devices).
